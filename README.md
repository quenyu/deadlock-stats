# Deadlock Ghost Match — clean-slate v2

Экспериментальный backend для одной продуктовой гипотезы: сравнить выбранный матч игрока с максимально похожей победой на том же герое и выдать одну измеримую цель на следующую игру.

## Почему отдельная ветка

Старая реализация смешивает доменные модели, UI-поля, старые ранги, кэширование, хранение и внешние API. Ветка `v2/clean-slate` намеренно не наследует старое дерево файлов.

## Что входит в первый MVP

- один источник данных: публичный Deadlock API;
- один use case: Ghost Match;
- один endpoint;
- стандартная библиотека Go без фреймворков;
- без PostgreSQL, Redis, JWT, Steam OpenID и фоновых worker'ов;
- unit-тесты алгоритма;
- честные ограничения анализа.

## Endpoint

```http
GET /api/v1/players/{accountID}/matches/{matchID}/ghost
```

`accountID` — числовой Deadlock/Steam account ID, который принимает upstream API.

Пример:

```bash
curl http://localhost:8080/api/v1/players/123456789/matches/987654321/ghost
```

## Локальный запуск

```bash
go test ./...
go run ./cmd/api
```

Переменные окружения:

- `PORT` — порт HTTP-сервера, по умолчанию `8080`;
- `DEADLOCK_API_BASE_URL` — upstream, по умолчанию `https://api.deadlock-api.com`.

## Что отчёт не утверждает

На данных обычной истории матчей нельзя достоверно установить момент ошибки, позиционирование, тайминги предметов или причинность поражения. Поэтому v2 сравнивает только доступные итоговые метрики и прямо возвращает ограничения.

Для временной шкалы, покупок и карты понадобится отдельный слой metadata/demo, который будет добавляться только после проверки стабильности API и стоимости обработки.
